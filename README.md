## 0. 设计原理（第一性原理，三条推出全部规则）

1. **真源必须唯一**：多副本必然漂移 → `main` 分支是唯一权威副本；**git 历史即备份**（每次 commit 自动保留上一版，可随时回滚），不再依赖本地磁盘与手工备份目录。本地/沙箱副本一律是临时工作副本，用完即弃。
2. **可信靠机器校验，不靠自觉**：一切写入必须经仓库自带校验器；校验不过 = 零写入。`original` 逐条 SHA-256 指纹 + meta 登记基准，校验器 fail-closed（meta 缺失即红灯）。**防意外损坏**：误改原文会被拦；**真防篡改**需 git 历史 + 签名 commit（指纹与数据同文件，同时改两头可自洽——所以 git 历史才是最终真源）。**禁止手工编辑 HTML 的 data/meta 块。**
3. **写后必回读**：推送 ≠ 成功。写入后重新拉取远端跑 `verify` 全绿才算完成；GitHub Actions 会对每次 push 自动再校验一遍兑底。

## 1. 铁律（2026-08-22 修订，不可破）

1. **只追加**：不删、不改老条目；文件名 `视频提示词库-多模型.html` 固定，不 bump 版本、不另存新文件。
2. **`original` 一个字符都不能变**：逐条指纹校验会拦截。
3. **一切写入只走 `追加提示词.py`**：它自动算 id/sha1/chars、全量校验、原地写回、自检；禁止手改数据块。
4. **仓库优先**（取代 2026-08-22 前的「本地优先」）：改库前先拉 main 最新，改完立即推回；git 历史即备份（脚本运行时生成的 `视频提示词库_备份/` 只是临时冗余，已 gitignore）。

## 2. 流程总览与通道选择

```
用户投自由格式素材（md / txt / 截图 / 粘贴文本 / 链接，任意格式）
     → AI 助手解析、归类、补全中文名/简介/标签/译文，生成 新条目.json（9 字段，§3）
     → 分类（§4）→ 拉最新库 → python 追加提示词.py
     → python 库维护工具.py verify（全绿）→ 推送 main → 回读远端 verify → 完成
```

> 素材 → 9 字段 JSON 的整理环节一律由 AI 助手完成，用户不手填字段；下表只是 JSON 就绪后按执行环境选机器通道。

| 执行环境 | 走哪条通道 |
|---|---|

## 3. 原料与数据格式

**原料从哪来**：① 用户在对话里直接给的提示词；② 采购/收集的 `.txt` `.json` 素材批次；③ 其它 AI 产出。无论哪种，先整理成 `新条目.json`（数组，一次可多条）。

**每条只需 9 个必填字段**（其余 id / sha1 / chars / langname / num / primary / srcs 由工具自动计算）：

| 字段 | 规则（校验器会逐条检查） |
|---|---|
| `model` | 「系列 + 空格 + 版本」：`Seedance 2.0` / `Seedance 2.5` / `海螺 H3` / `可灵 O3` / `可灵 3.0`；没空格直接拒绝 |
| `cat` | 大类，优先用 §4 现有 14 类 |
| `sub` | 子类，优先复用 §4 现有子类；新建用「X·Y」式 |
| `name` | **中文**标题（无中文字符即拒绝） |
| `desc` | **中文**一句话简介 |
| `tags` | **数组**，3–6 个；中文词，或白名单技术标签 FPV/IMAX/CG/UE5/AI/VFX/HDR/LUT/Glitch/Motion/Logo/Arri/Bokeh/Loop，或数字开头、全大写缩写 |
| `lang` | `zh` 或外文代码（`en` 等） |
| `original` | 提示词原文，**逐字保留**（中文放中文；外文放外文原文） |
| `src` | 来源，如 `用户直供`、`seedance2.0收集6#1` |

可选：`zh`（**外文条目必填**中文译文）、`srcs`（来源文件列表）、`num`、`primary`。

示例：

```json
[
  {
    "model": "Seedance 2.0",
    "cat": "动作·打斗",
    "sub": "近身·格斗",
    "name": "雨夜巷战·慢镜近身",
    "desc": "雨水沿刀刃滑落，慢动作近身格斗，霓虹反光。",
    "tags": ["打戏", "慢动作", "雨夜", "AI视频"],
    "lang": "zh",
    "original": "雨夜巷战，慢镜头近身格斗，雨水沿刀刃滑落……",
    "src": "用户直供"
  }
]
```

**提交前自检清单**：

- [ ] 9 字段全有；`tags` 是**真数组**不是字符串
- [ ] `model` 带空格且尽量在注册表内；全新模型先与维护者确认
- [ ] `name` `desc` 含中文；`tags` 3–6 个且合规
- [ ] `lang` ≠ `zh` 时 `zh` 译文已填
- [ ] `original` 与素材逐字一致，无乱码字符 �
- [ ] 不与库内已有条目重复（工具会去空白逐字比对，重复会被拦）

## 5. 通道 A：全流程自理（能跑 Python 的 AI / 人，推荐）

```bash
# 1) 拉最新库（三选一）
git clone --depth 1 https://github.com/YIJUEYIJUE/video-prompt-library.git
# 或只拉单文件：
curl -LO "https://raw.githubusercontent.com/YIJUEYIJUE/video-prompt-library/main/视频提示词库-多模型.html"
# 或用你平台自带的 GitHub 工具读取文件

# 2) 写好 新条目.json 后追加（自动校验，不过 = 零写入）
python 追加提示词.py "视频提示词库-多模型.html" 新条目.json

# 3) 只读核验，必须全绿
python 库维护工具.py verify "视频提示词库-多模型.html"

# 4) 推送（三选一）
git add "视频提示词库-多模型.html" && git commit -m "追加 N 条：<简述>" && git push
# 或 GitHub API：PUT /repos/YIJUEYIJUE/video-prompt-library/contents/<文件名>
#    body: { message, branch: "main", sha: <远端当前 blob sha>, content: <base64> }

# 5) 回读核验：重新下载远端文件 → 再跑一遍 verify → 条目数 = 老条数 + N
```

注意：

- 提交信息统一 `追加 N 条：<简述>`。
- 同一时间只推一次；推送被拒（non-fast-forward）就重新拉库重做，**不要 force push**。
- Windows 写出的 CRLF 换行不影响校验与指纹，无需处理。
- 铁证法：本地追加后记下 verify 输出的「全库指纹」，回读远端再 verify 一遍——指纹完全一致 = 全程逐字节无损。

## 6. 通道 B：`待入库/` 自动入库（跑不了 Python 的 AI）

**方式一 · 小批次 JSON**：按 §3 整理 `<批次名>.json`（数组），提交到仓库 `待入库/` 目录（网页上传或 API PUT 均可）。

**方式二 · `.url` 直链（大批次 / 要求字节精确时首选）**：不要把大 JSON 塞进对话或工具参数里转写（转写必错），改为提交一个两行文本文件 `待入库/<批次名>.url`：

```
第 1 行：指向 JSON 文件的公网 HTTPS 直链（临时签名链接即可：对象存储/网盘/Notion 附件直链）
第 2 行：该 JSON 文件的 SHA-256（64 位小写十六进制）——**必填**；留空时 CI 只打印哈希不做比对，字节校验即失效
```

CI 会先下载、再 `sha256sum -c` 强校验——哈希不符 = 红灯，一个字节都不会写入。「源提示词一个字不错」由机器兑现，不靠小心。

**CI 都做什么**（`.github/workflows/append.yml`）：下载/读取批次 → sha256 校验（方式二）→ 逐个 `追加提示词.py`（全量校验，不过=零写入）→ `库维护工具.py verify` 全绿 → 批次原件归档 `已入库/`（时间戳前缀）→ 全过程写入 `运行记录/最近入库.log`（含 verify 输出与最新全库指纹）→ 自动提交 `CI 自动入库：追加 N 条 → 共 M 条`。

**怎么确认成功**：① Actions 绿勾；② 最新 commit 信息里 N/M 条数对得上；③ `运行记录/最近入库.log` 里 verify 全绿；④（铁证）若你先在本地试跑过：日志里的全库指纹与你本地试跑结果完全一致 = 全程逐字节无损。红灯 = 一条都没写入，库文件不会半坏；看日志修正后重新提交。

> 2026-08-22 实测：28 条批次（441,635 字节 JSON）经方式二入库，本地/云端全库指纹一致（`aff00674d4bedb6e`），全程 9 秒。

## 7. 防错体系（怎么确保不出错）

| 层 | 机制 |
|---|---|
| 写入前 | 工具全量校验（字段/中文/标签/译文/重复/指纹），**不过 = 零写入**；通道 B 另有 sha256 强校验把关传输 |
| 写入时 | 只追加、版本标签不变；写回后内置自检（条数、老原文未动） |
| 推送后 | CI `verify.yml` 对每次改库 push 自动校验，README 顶部徽章可见 |
| 你自己 | 回读远端再跑一遍 `verify`（§5 第 5 步）；对比全库指纹拿铁证 |

常见拒绝原因速查：缺字段 / model 没空格 / 标题或简介无中文 / 标签数不在 3–6 / 小写英文标签（不在白名单）/ 外文缺 zh / original 与库内重复 / 老条目指纹不符（= 改了原文或手改了数据块）。

## 8. 坑与防错清单（每条都有来历，硬性遵守）

**A · 源提示词：一个字都不能错**

1. **禁止人肉转录原文**：不许手敲、复述、「顺手润色」、改标点。只允许机器搬运：整文件复制、直链下载。长文本经对话窗口转手会被悄悄截断/吞段——大批次一律走 §6 方式二的文件直链。
2. **上传前后对 SHA-256**：新条目的 `original` 在入库前还没有历史指纹保护，来源侧错了工具拦不住——所以来源文件与提交件必须哈希一致（`.url` 第 2 行强制做这件事）。
3. **外文条目必带 `zh` 全文译文**：翻译超长原文要分段推进、最后检查结尾是否译完——「翻到一半断掉」肉眼难察觉，校验只能查「有没有」查不了「全不全」。
4. **乱码零容忍**：出现 U+FFFD（�）= 编码搬运出错，校验器直接拒绝；统一 UTF-8（无 BOM）。

**B · 库文件：原版 HTML 不能改坏**

1. **永不手改** `<script id="data">` / `<script id="meta">`，一个标点都不行；写入只走 `追加提示词.py`。
2. **别用错工具**：`库维护工具.py` 只用它的 `verify` / `export`（`add` 已于 2026-08-26 物理删除——它与 追加提示词.py 功能重复且指纹算法 64 位不一致，曾存在指纹分裂风险）。
3. CRLF/LF 换行差异无害（指纹按内容计算），不要为此「修复」库文件。
4. 怀疑改坏了就跑 `verify`：全绿 = 没坏；任何红 = 停手走 §9 回滚，不要带伤继续操作。
5. 库文件 1.8MB+：**永远不要**把它整个贴进对话/工具参数里转写；需要传输时走直链或 git。

**C · 推送与并发**

1. 一次只推一个批次；被拒（non-fast-forward）= 有并发写入，重新拉最新库重做，**绝不 force push**、绝不改写历史。
2. API 直传 HTML 必须带远端当前 blob sha；传前传后各跑一遍 verify 并核对条目数。
3. CI 的自动提交不会再触发 `verify.yml`（GITHUB_TOKEN 特性），不是故障——`append.yml` 内部已跑过 verify，凭证在 `运行记录/最近入库.log`。
4. 签名直链有效期短（常见 1 小时）：生成后立即推 `.url` 让 CI 消费；过期就重新生成再推，旧 `.url` 会被归档不必管。

**D · 字段与分类**

1. `tags` 必须是 JSON 真数组（`["a","b"]`），字符串形式直接拒。
2. `model` 必须「系列 空格 版本」；新模型系列需先确认 id 前缀注册（已占用：sd2 / sd25 / hl3 / klo3 / kl3）。
3. 分类先复用 §4，克制造新类冲动（2026-08-22 批次 28 条实测：21 条复用旧子类，仅 7 个确无归属才新建）。
4. `src` 写可溯源批次（如 `video_prompts.json#7`、`用户直供#3`）——出错回查全靠它。

**E · 凭证**

1. `.gh_token` 等任何密钥永不写入被提交的文件/提交信息/日志。`.gitignore` 已设防，但不要去试探。

## 9. 回滚（出错了怎么办）

- 还没推送：扔掉工作副本，重新拉库重做。
- 已推送但 CI 红灯 / 发现写坏：`git revert <坏提交SHA> && git push`；或从历史提取好版本：`git show <好提交SHA>:"视频提示词库-多模型.html" > 恢复.html`，替换后按 §5 重推。
- 禁止 force push、禁止改写历史——**历史就是备份**。

## 10. 导出与导出核验

```bash
python 库维护工具.py export "视频提示词库-多模型.html" 导出目录   # 目录需已存在
```

产物：`AI知识库包-全库-N条.md`（无损镜像，给 AI 整库阅读）、`AI导读索引-全库-N条.md`（轻量）、`提示词库-全库-N条.jsonl / .json / .md / .txt`、`维护日志.md`。

导出正确性核验：① export 前 `verify` 必须全绿；② 文件名里的 N = 库条目数；③ JSONL 行数 = N；④ 抽查 3 条 `prompt` 与库内 `original` 逐字一致。导出物**不入仓库**（防膨胀），谁需要谁现场导。
