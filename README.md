## 0. 设计原理（第一性原理，三条推出全部规则）

1. **真源必须唯一**：多副本必然漂移 → `main` 分支是唯一权威副本；**git 历史即备份**（每次 commit 自动保留上一版，可随时回滚），不再依赖本地磁盘与手工备份目录。本地/沙箱副本一律是临时工作副本，用完即弃。
2. **可信靠机器校验，不靠自觉**：一切写入必须经仓库自带校验器；校验不过 = 零写入。`original` 逐条 SHA-256 指纹，改一个字都会被拦。**禁止手工编辑 HTML 的 data/meta 块。**
3. **写后必回读**：推送 ≠ 成功。写入后重新拉取远端跑 `verify` 全绿才算完成；GitHub Actions 会对每次 push 自动再校验一遍兑底。

## 1. 铁律（2026-08-22 修订，不可破）

1. **只追加**：不删、不改老条目；文件名 `视频提示词库-多模型.html` 固定，不 bump 版本、不另存新文件。
2. **`original` 一个字符都不能变**：逐条指纹校验会拦截。
3. **一切写入只走 `追加提示词.py`**：它自动算 id/sha1/chars、全量校验、原地写回、自检；禁止手改数据块。
4. **仓库优先**（取代 2026-08-22 前的「本地优先」）：改库前先拉 main 最新，改完立即推回；git 历史即备份（脚本运行时生成的 `视频提示词库_备份/` 只是临时冗余，已 gitignore）。

## 2. 流程总览与通道选择

```
拿原料 → 整理 新条目.json（9 字段）→ 分类（§4）→ 拉最新库 → python 追加提示词.py
     → python 库维护工具.py verify（全绿）→ 推送 main → 回读远端 verify → 完成
```

| 你的能力 | 走哪条通道 |
|---|---|
| 能跑 Python 且能推送（沙箱 / 本机 / 带 GitHub 工具的 AI） | **A · 全流程自理（§5，推荐）** |
| 只能向仓库提交文件，跑不了 Python | **B · 把 JSON 放进 `待入库/`，CI 自动入库（§6）** |
| 两样都不行 | **C · 把整理好的 JSON 交给用户或任一有权限的协作者** |

## 3. 原料与数据格式

**原料从哪来**：① 用户在对话里直接给的提示词；② 采购/收集的 `.txt` `.json` 素材批次；③ 其它 AI 产出。无论哪种，先整理成 `新条目.json`（数组，一次可多条）。

**每条只需 9 个必填字段**（其余 id / sha1 / chars / langname / num / primary / srcs 由工具自动计算）：

| 字段 | 规则（校验器会逐条检查） |
|---|---|
| `model` | 「系列 + 空格 + 版本」：`Seedance 2.0` / `Seedance 2.5` / `海螺 H3` / `可灵 O3`；没空格直接拒绝 |
| `cat` | 大类，优先用 §4 现有 14 类 |
| `sub` | 子类，优先复用 §4 现有子类；新建用「X·Y」式 |
| `name` | **中文**标题（无中文字符即拒绝） |
| `desc` | **中文**一句话简介 |
| `tags` | **数组**，3–6 个；中文词，或白名单技术标签 FPV/IMAX/CG/UE5/AI/VFX/HDR/LUT/Glitch/Motion/Logo/Arri/Bokeh/Loop，或数字开头、全大写缩写 |
| `lang` | `zh` 或外文代码（`en` 等） |
| `original` | 提示词原文，**逐字保留**（中文放中文；外文放外文原文） |
| `src` | 来源，如 `用户直供`、`seedance2.0收集6#1` |

可选：`zh`（**外文条目必填**中文译文）、`srcs`（来源文件列表）、`num`、`primary`。

示例：

```json
[
  {
    "model": "Seedance 2.0",
    "cat": "动作·打斗",
    "sub": "近身·格斗",
    "name": "雨夜巷战·慢镜近身",
    "desc": "雨水沿刀刃滑落，慢动作近身格斗，霓虹反光。",
    "tags": ["打戏", "慢动作", "雨夜", "AI视频"],
    "lang": "zh",
    "original": "雨夜巷战，慢镜头近身格斗，雨水沿刀刃滑落……",
    "src": "用户直供"
  }
]
```

**提交前自检清单**：

- [ ] 9 字段全有；`tags` 是**真数组**不是字符串
- [ ] `model` 带空格且尽量在注册表内；全新模型先与维护者确认
- [ ] `name` `desc` 含中文；`tags` 3–6 个且合规
- [ ] `lang` ≠ `zh` 时 `zh` 译文已填
- [ ] `original` 与素材逐字一致，无乱码字符 �
- [ ] 不与库内已有条目重复（工具会去空白逐字比对，重复会被拦）

## 5. 通道 A：全流程自理（能跑 Python 的 AI / 人，推荐）

```bash
# 1) 拉最新库（三选一）
git clone --depth 1 https://github.com/YIJUEYIJUE/video-prompt-library.git
# 或只拉单文件：
curl -LO "https://raw.githubusercontent.com/YIJUEYIJUE/video-prompt-library/main/视频提示词库-多模型.html"
# 或用你平台自带的 GitHub 工具读取文件

# 2) 写好 新条目.json 后追加（自动校验，不过 = 零写入）
python 追加提示词.py "视频提示词库-多模型.html" 新条目.json

# 3) 只读核验，必须全绿
python 库维护工具.py verify "视频提示词库-多模型.html"

# 4) 推送（三选一）
git add "视频提示词库-多模型.html" && git commit -m "追加 N 条：<简述>" && git push
# 或 GitHub API：PUT /repos/YIJUEYIJUE/video-prompt-library/contents/<文件名>
#    body: { message, branch: "main", sha: <远端当前 blob sha>, content: <base64> }
# 或维护者本机：python git_push.py "追加 N 条：<简述>"（读本机 .gh_token）

# 5) 回读核验：重新下载远端文件 → 再跑一遍 verify → 条目数 = 老条数 + N
```

注意：
- 提交信息统一 `追加 N 条：<简述>`。
- 同一时间只推一次；推送被拒（non-fast-forward）就重新拉库重做，**不要 force push**。
- Windows 写出的 CRLF 换行不影响校验与指纹，无需处理。

## 6. 通道 B：`待入库/` 自动入库（跑不了 Python 的 AI）

1. 按 §3 整理出 `<批次名>.json`（数组）。
2. 提交到仓库 `待入库/` 目录（网页上传或 API PUT 均可）。
3. GitHub Actions（`.github/workflows/append.yml`）自动：逐个 `追加提示词.py` → `verify` → 把处理完的 JSON 挪到 `已入库/` → 提交推送。
4. 去 Actions 页看结果：**绿 = 已入库**；红 = 一条都没写入，看日志改 JSON 后重新提交。

## 7. 防错体系（怎么确保不出错）

| 层 | 机制 |
|---|---|
| 写入前 | 工具全量校验（字段/中文/标签/译文/重复/指纹），**不过 = 零写入** |
| 写入时 | 只追加、版本标签不变；写回后内置自检（条数、老原文未动） |
| 推送后 | CI `verify.yml` 对每次改库 push 自动校验，README 顶部徽章可见 |
| 你自己 | 回读远端再跑一遍 `verify`（§5 第 5 步） |

常见拒绝原因速查：缺字段 / model 没空格 / 标题或简介无中文 / 标签数不在 3–6 / 小写英文标签（不在白名单）/ 外文缺 zh / original 与库内重复 / 老条目指纹不符（= 改了原文或手改了数据块）。

## 8. 回滚（出错了怎么办）

- 还没推送：扔掉工作副本，重新拉库重做。
- 已推送但 CI 红灯 / 发现写坏：`git revert <坏提交SHA> && git push`；或从历史提取好版本：`git show <好提交SHA>:"视频提示词库-多模型.html" > 恢复.html`，替换后按 §5 重推。
- 禁止 force push、禁止改写历史——**历史就是备份**。

## 9. 导出与导出核验

```bash
python 库维护工具.py export "视频提示词库-多模型.html" 导出目录   # 目录需已存在
```

产物：`AI知识库包-全库-N条.md`（无损镜像，给 AI 整库阅读）、`AI导读索引-全库-N条.md`（轻量）、`提示词库-全库-N条.jsonl / .json / .md / .txt`、`维护日志.md`。

导出正确性核验：① export 前 `verify` 必须全绿；② 文件名里的 N = 库条目数；③ JSONL 行数 = N；④ 抽查 3 条 `prompt` 与库内 `original` 逐字一致。导出物**不入仓库**（防膨胀），谁需要谁现场导。

## 10. 仓库结构

| 文件 | 作用 |
|---|---|
| `视频提示词库-多模型.html` | **唯一数据源**（data + meta），只追加 |
| `追加提示词.py` | 日常唯一写入入口：校验→写回→自检 |
| `库维护工具.py` | 只读 `verify` / `export`（`add` 为旧版带版本输出模式，日常不用） |
| `待入库/` | 通道 B 收件箱：放 9 字段 JSON，CI 自动入库 |
| `已入库/` | CI 处理完的 JSON 存档（自动生成） |
| `.github/workflows/` | `verify.yml` 推送校验；`append.yml` 自动入库 |
| `提示词库说明.md` | 深度规格（17 字段、HTML 结构、工具源码） |
| `git_push.py` | 维护者本机推送脚本（读本机 `.gh_token`，可选） |
| `index.html` / `.nojekyll` | GitHub Pages 入口 / 禁用 Jekyll |

`.gh_token`、`新条目.json`、`视频提示词库_备份/` 等永不入库（见 `.gitignore`）。**任何 token / 密钥严禁写进任何被提交的文件。**
